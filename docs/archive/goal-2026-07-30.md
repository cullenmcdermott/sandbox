## Before any code

0. **No git in-pod — by design, not a breakage.** `.git` is a pointer file
   naming a host path that isn't mounted here (`detached-worktree`,
   `runner/src/workspace-guide.ts:60`). `git status`/`diff`/`commit`/`mv` all
   fail; do not `git init`, delete, or rewrite `.git`. Edits sync to the host
   via mutagen and the maintainer commits there. Consequence for this goal:
   verification is tests-only (no diffing against HEAD), "`git mv` to
   archive" becomes a plain file move, and batch boundaries are reported to
   the maintainer rather than committed. Also note the tree carries an
   uncommitted 2026-07-28/29 diff (codex connect forward, PTY repaint jiggle
   hold, Dockerfile bumps) that several findings are about — it is present in
   the working tree and is what you are reading.
1. **Triage into `TODO.md`** per its "How to use this file" preamble: new
   items into the matching workstreams (§1 bugs / §4 perf / §2e pane), each
   pointing back at `docs/review-2026-07-30.md` by id.
2. **Re-verify each finding against the actual tree** before scheduling it.
   This review was produced by inspection, not measurement — some may already
   be fixed, some may be wrong. Report anything that doesn't hold up rather
   than implementing it anyway.

## How to run it

- Delegate each batch to a subagent with the finding text, the re-verified
  pointers, and the acceptance bar. Do not hand one agent two batches that
  touch the same files (B, C, D, and X1/X2 all live in `client/session.go` —
  serialize those).
- **You integrate. You run the gate.** Per change, run the tests named in the
  item; `just check` once per batch. Mind the CLAUDE.md sandbox caveats:
  `client`, `client/models`, `internal/runner`, `internal/k8s` need the
  command sandbox disabled.
- `[R1]`/`[R3]`/`[R6]` are latency claims. Land them with a **measurement**,
  not an assertion — time a warm reattach before and after and put the number
  in the done-log line.
- Anything exported from `client/` or `tui/` is governed by
  [`docs/design-principles.md`](design-principles.md) and needs an `sdktest/`
  pin in the same change.
- Docs are part of done: `docs/runner-api.md` for the pane upgrade params and
  any new readiness field, `docs/architecture.md` if the connect flow changes.
